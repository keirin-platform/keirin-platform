# マルチビュー（複数場のライブ同時視聴）設計

2026-10-21 にオーナーと詰めた設計。実装はこれから。

## 目的と背景

ミッドナイトなどで、3場ほどが数分おきに発走することがよくある。車券を買うかどうかに関係なく、レースとして全部見たい。
今は場ごとにブラウザのタブを切り替えていて忙しい。**1つの画面で、タブを切り替えずに複数場のライブを見られる**ようにする。

## 目標

- 各場の**公式 YouTube ライブ**を、ビューアの1ページに最大4枠で並べる。
- その日に開催している場から、映す場を選べる。
- 次に発走する場が、ひと目で分かる。

## やらないこと

- スマホやタブレット向けの画面（オーナー判断。小さすぎて複数画面に向かない）。**ノート PC が前提**。
- 出走表や予想を画面に載せること（必要なら既存のビューアで見る）。
- KEIRIN.JP のライブ中継（`/pc/racelive` は robots.txt で許可されていない）や、投票サイトの映像の利用。
- 録画、見逃し再生。

## やってはいけないこと（動いても失敗とみなす）

- **音を自動で切り替える**こと。オーナーは解説者のコメントを聞きたいこともあるので、音は**完全に使う人が決める**。
- **枠の大きさや位置が自動で変わる**こと。発走が遅れてタイミングが重なると煩わしいため（オーナー指摘）。
- 枠の強調の変化や、ほかの枠の入れ替えで、**見ている映像が読み込み直されて止まる**こと。
- YouTube のページを機械的に読み取ること（YouTube の利用規約に反する）。配信の検索は **YouTube Data API** だけで行う。
- 発走状況を知るために keirin.jp へ頻繁に問い合わせること（控えめな収集の方針。CLAUDE.md「データソース」）。

## 画面

- 置き場所: 今の Streamlit ビューアに「マルチビュー」のページを追加する（`layout="wide"`）。マルチビューのページでは、サイドバーを閉じた状態で始める。
- **2×2 の固定グリッド**で、映像の位置と大きさは変わらない。
  - 3場以下なら、空いた枠に「次の発走」の一覧（場・R・予定時刻を発走順に）を置く。
  - 4場のときは、一覧を枠の外（グリッドの上の帯）に出す。
- 各枠の上に1行で、場名、時間帯、次の R と**予定**の発走時刻（「予定 23:41」）、発走までの残り時間を出す。
- **強調**: 次に発走する場の枠（見出し、または枠線）の色を変える。動かすのは色だけ。
  - 予定時刻だけで判断する。予定時刻を過ぎたら、その場は「発走待ち」と表示し、予定時刻から**5分**たったら強調を次の発走予定の場へ移す（5分はオーナー確認前の仮の値。後で調整してよい）。
  - レースの終了を keirin.jp に問い合わせることはしない。発走の遅れは稀（オーナー情報）なので、ずれても見た目だけの問題で済む。
- **音**: 埋め込みは `autoplay=1&mute=1` で始める（ブラウザはミュートでないと自動再生しない）。音のオン・オフは YouTube プレーヤー自身のボタンで、使う人が行う。複数の枠を同時に鳴らしてもよい。アプリ側で音を操作しない。

## 場の選び方

- その日に開催している場（`store.meetings(today)`）を、場名、時間帯（モーニング／デイ／ナイター／ミッドナイト）、次の R の発走予定を添えて、チェックボックス（または multiselect）で並べる。
- **最大4場**。5場目は選べないようにする。
- 最初の選択は、**今から近い時刻に発走する順で最大3場**（Claude の判断）。全レースが終わった場は候補の下に回す。
- 選択を変えたとき、**変わった枠だけ**を読み込み直す。残した場の映像は止めない。
- ミッドナイトの発走は同じ日付の 21〜24 時台に収まるので、日付は JST の今日だけを扱えばよい。
- 「次の発走」の一覧には、**映している場だけ**を並べる。開催しているすべての場の次の発走は、場を選ぶ欄のほうに出す（Claude の判断）。

### 今日の発走予定の取り方（keirin.jp へのアクセス）

- 今日の分はまだ収集されていないので、発走予定は keirin.jp から取る（`store.races`。収集前の日は keirin.jp から取得する）。
- 使うのは**予定時刻だけ**で、1日の間に変わらない。そこで、マルチビューでは**開催ごとに1日1回だけ取り、その日のあいだはずっと使う**（Claude の判断）。今のビューアの5分キャッシュとは別に、日付をキーにした長いキャッシュを持つ。
  1日に増えるアクセスは、開催の数（多い日で10件前後）だけになり、控えめな収集の方針に収まる。
- 取得に失敗した場は、場を選ぶ欄に「発走予定を取得できません」と出し、映像の表示はできるようにする（強調と残り時間だけが出ない）。

## 配信の見つけ方

### 前提（2026-10-21 の調査）

- **全43場に公式 YouTube チャンネルがある**。出典は Kドリームスと netkeirin のライブ映像一覧。各チャンネルの ID を確認した（下の表）。
- 配信は数日前から予約（upcoming）されていて、予定の開始時刻がある。調べた範囲では、ライブ動画はすべて埋め込みで再生できた（`playableInEmbed: true`）。
- **場とチャンネルは1対1ではない**。
  - 借り上げ開催（バンク改修などで、ほかの場を借りて開催する）では、タイトルに施行者と実際の場が両方入る。例: 「高松市営玉野競輪」「【富山市営】松阪競輪」。施行者と実際の場の**両方のチャンネルで同時に配信されることがある**（オーナー観察）。
  - そのほかの例: 高松のチャンネルで松山のモーニング、いわき平のチャンネルで「函館inいわき平」を配信していた。
  - 開催データ（`meetings.venue_name`）は**実際に走るバンク**で記録されている（高松が借り上げた開催も「玉野」）。
- レース以外のライブもある（例: 函館のチャンネルで熊本の「【競輪予想】」番組）。
- タイトルの日付の書き方はばらばら（「10/21」「2026.10.24」「2026年10月27日」、日付なしで「3日目」だけ、など）。

### 方法

1. 下の表のチャンネルごとに、アップロード再生リスト（`UC…` の `UU…`）を `playlistItems.list` で取り、新しい動画を数件見る（1回1ユニット）。
2. 候補をまとめて `videos.list`（`part=snippet,liveStreamingDetails,status`、50件で1ユニット）にかけ、ライブ中または予約中で、予定開始時刻（または実際の開始時刻）が JST の今日のものだけを残す。
3. **場の照合**:
   - タイトルから、施行者の表記（「〇〇市営」「【〇〇市営】」など）を取り除く。
   - 「X in Y」の形なら、Y を実際の場とする。
   - 残りに含まれる場名で、開催データの場に対応づける。表記ゆれ（伊東／伊東温泉、向日町／京都向日町、岸和田／ブッキースタジアム岸和田、千葉／JPF ドーム など）は別名表で吸収する。
   - 「予想」を含むタイトルは除外する。
   - 同じ場の開催が複数の時間帯にまたがることはない前提でよい。予定開始時刻が開催の時間帯（最初のレースの発走予定の数時間前〜最終レース）に入っていることも確かめる。
4. 同じ場に候補が複数ある（借り上げで両方のチャンネルが配信しているなど）ときは、**実際の場の公式チャンネルを優先**する（Claude の判断）。
5. 見つからない場の枠には「配信が見つかりません」と表示し、**YouTube の URL を手で貼れる**入力欄を出す。貼った URL はそのセッションの間だけ使う。
6. 見つかった枠にも、小さな「配信を差し替え」（URL の手入力）を付ける（Claude の判断）。照合はタイトル頼みで、借り上げ開催や他場の番組で外すことがあるため。**手で貼った URL は自動の照合より優先**し、15分ごとの検索結果の更新でも上書きしない。

### API の使い方

- キーは Streamlit の Secrets と、ローカルでは環境変数 `YOUTUBE_API_KEY`（オーナーが 2026-10-21 に発行済み。Secrets への登録はまだ）。キーがなければ、マルチビューのページに「API キーが未設定」と出し、URL の手入力だけで使えるようにする。
- 検索結果は**15分キャッシュ**する（全チャンネルで1回約50ユニット。1日中開きっぱなしでも約4,800ユニットで、無料枠の 10,000 に収まる）。`search.list`（1回100ユニット）は使わない。
- API のエラーやクォータ切れのときは、ページを壊さず、該当の枠を「配信が見つかりません」と同じ扱いにする。

## 実装の制約

- Streamlit は操作のたびにスクリプトを再実行する。**同じ動画の枠が再実行で作り直されない**ように作る（例: 枠ごとに同じ引数で `st.iframe` 相当を描き、残り時間や強調の更新は `st.fragment(run_every=...)` で見出しだけに閉じる）。具体的な方法は実装に任せるが、「やってはいけないこと」の映像の読み込み直しは、実際のブラウザで確かめる。
- テストは架空の API レスポンスで書く（実データや実際のキーを使わない。CLAUDE.md の方針）。照合のテストには、上に挙げた実例のタイトルの形（市営、in、予想、日付なし）を架空の値で入れる。
- ビューアを変えたら、データリポジトリの `requirements.txt` の SHA を更新する PR も出す（docs/deploy-streamlit.md）。
- `.superpowers/`（設計時のモック置き場）を `.gitignore` に追加する。
- CLAUDE.md の「オーナーの要望」に9番目としてこの機能を、「決定ログ」に決めたことを追記する。

## 実装に任せること

- モジュールの分け方（例: `youtube.py` に API と照合、`viewer.py` にページ）、ページの追加方法（`st.navigation` など）。
- 枠の見た目、色、残り時間の更新間隔（1分以内）。
- 別名表の中身（上の例を含めること）。
- 「発走待ち」の5分は仮の値で、運用して調整してよい。
